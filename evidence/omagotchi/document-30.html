MVP 완료 기준

M1: 내부 사용 MVP

다음 흐름이 운영 서버에서 한 번에 동작해야 합니다.

계정 생성
  → 로그인·인증 갱신
    → 교육 기수 참가 신청·승인
      → 보호된 Learning API 접근
        → 타이머 시작·정지
          → 확정 공부 기록·일간 합계 조회

4주차 말까지 아래 기능을 배포하면 M1-ready, #218에서 3영업일 실사용 검증까지 끝내면 M1 완료입니다.

- 인증·계정: #213, #214, #215, #216의 관리자 Bootstrap과 계정 상태 차단

- 교육 기수·소속: #251~#255의 기수, 가입 코드, 신청·승인, MANAGER·STUDENT 최소 역할

- 타이머·공부 기록: #190~#196, 단 #196에 본인 당일 기록 목록과 최소 일간 합계를 포함

- 배포: #217과 Identity·Learning Smoke Test

- 프론트: 로그인, 교육 기수 참가·승인, 타이머 시작·정지, 당일 기록 조회의 최소 화면과 API 연동

- 운영 전환: 위 항목 완료 후 #218을 시작하고 3영업일 동안 실제 데이터를 축적

일간 합계의 날짜 경계는 #196 구현 전에 정합니다. 04:00 집계 기준을 처음부터 사용한다면 #201의 관련 범위를 4주차로 당기고, 복잡한 기록 분할만 6주차에 남깁니다.

#238 본인 계정 관리, #239 시스템 관리자 계정 관리, 커뮤니티, 상세 게이미피케이션과 모니터링 완성은 M1 시작을 막지 않습니다. #219 Request ID와 로그 추적은 내부 사용을 시작한 5주차 안에 완료해 초기 오류를 추적할 수 있게 합니다.

M2: 제품 MVP

M1에 다음 결과를 추가합니다.

- 입실·퇴실, 현재 상태와 본인·기수 관리자 최소 조회

- 확정 공부 시간 기반 개인 일간·주간·월간 랭킹

- 기본 캐릭터 한 종류와 고정 퀘스트 한 종류

- MQTT 수신부터 정규화, 품질 판정, RabbitMQ 발행, InfluxDB 적재까지의 센서 흐름

- 기수 관리자가 사용자·출결·학습·센서 현황을 확인할 최소 대시보드

공간 목록·상태와 회의실 점유·반납·자동 만료는 Google Sheets에서 해당 요구사항의 수용 여부를 확정한 경우에만 M2에 포함합니다. 새 공간·팀 명세는 현재 Draft이므로 요구사항 원본보다 우선하지 않습니다.

복합 랭킹 점수, EXP·레벨·배지, 개인화 퀘스트, 파일 첨부, 실시간 채팅·알림, Rule Engine 이중화는 M2 완료 조건이 아닙니다.

일정 변경 기준

일정이 밀리면 다음 순서로 범위를 줄입니다.

1. Later 항목을 제거합니다.

2. F 항목의 고도화·편의 기능을 제거합니다.

3. M2는 최소 조회·표시만 남기고 관리·자동화 고도화를 줄입니다.

4. M1의 계정·기수·인증·타이머·배포 수직 흐름은 유지합니다.

M1 핵심 경로가 지연되면 담당자를 추가하거나 다른 파트의 후순위 일정을 멈춥니다. 커뮤니티·이중화·파일 첨부를 먼저 완성하고 내부 사용 시작을 늦추지 않습니다.
