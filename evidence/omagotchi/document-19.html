전체 목차

- 상태: 작업 기록

배경

홈을 React 영역으로 나누는 과정에서 기존 home.css의 전체 화면 레이아웃과<br>react-stage.css의 모바일/HUD 레이아웃이 동시에 적용됐다. 그 결과 뷰포트의<br>가로·세로 비율이 달라질 때 요소가 자연스럽게 재배치되지 않고 잘리거나 겹쳤다.

확인한 핵심 문제

1. body, .home-page, .home-hero에 height: 100vh/100dvh와<br>overflow: hidden이 중복 적용되어 문서 스크롤이 차단됐다.

2. 캐릭터 상태, 경험치, 채팅, 빠른 실행 버튼이 서로 다른 파일에서<br>position: fixed/absolute와 개별 좌표를 사용해 대각선 리사이즈 시 정렬 기준이<br>달라졌다.

3. 모바일 세로/가로 전환을 높이와 방향별 예외 규칙으로 해결해 중간 비율에서<br>규칙이 충돌했다.

4. scrollCue.css와 scrollCue.js가 홈에도 로드되어 우측 하단에 삼각형 안내<br>도형을 생성했다.

변경 내용

- home-responsive.css를 홈 스타일의 마지막에 로드해 한 개의 최종 레이아웃<br>계약을 만들었다.

- 화면 전체는 min-height: 100svh만 보장하고 콘텐츠 높이가 커지면 문서가<br>자연스럽게 늘어나도록 변경했다.

- React 홈 스테이지는 정상 문서 흐름의 Grid로 구성했다. 메뉴, 타이머, 캐릭터,<br>상태 HUD 순서를 유지하면서 하단 HUD의 고정 좌표를 제거했다.

- 1023px 이하에서는 메뉴를 4열로, HUD를 2단으로 바꾸고, 560px 이하에서는<br>HUD를 한 열로 쌓는다.

- 높이가 짧은 가로 화면은 별도 좌표 대신 콘텐츠 크기와 간격만 줄인다. 콘텐츠가<br>뷰포트보다 크면 스크롤로 접근할 수 있다.

- 홈 템플릿에서 scrollCue.js를 제거하고 홈 전용 CSS에서 삼각형 pseudo-element를<br>비활성화했다.

- 닫힌 BGM 패널은 pointer-events: none을 유지하고 실제로 열렸을 때만 입력을<br>받도록 해 하단 HUD 버튼을 가로막지 않게 했다.

- env(safe-area-inset-*)를 적용해 노치와 홈 인디케이터 영역을 피한다.

- clamp()를 사용해 타이머, 캐릭터, 메뉴, 버튼 크기가 뷰포트에 따라 연속적으로<br>변하도록 했다.

- 로고와 내비게이션을 같은 상단 Grid 흐름에 두고 반응형 간격을 추가해 서로<br>붙어 보이지 않도록 했다.

유지한 동작

- 메뉴 오버레이 진입

- 타이머 시작/정지

- 캐릭터 상호작용과 말풍선

- 경험치 및 레벨 표시

- 채팅 패널 토글과 모바일 스와이프

- 출석, 재실 인원, BGM 패널

검증 기준

- 데스크톱: 1440×900, 1280×720

- 태블릿/가로 모바일: 1024×768, 844×390

- 모바일: 390×844, 360×640

- 모든 크기에서 가로 오버플로가 없고, 세로 콘텐츠가 넘치면 스크롤 가능해야 한다.

- 우측 하단 삼각형이 표시되지 않아야 한다.

- 메뉴와 빠른 실행 버튼은 포인터/키보드로 접근 가능해야 한다.

로컬 실행 및 확인

SPRING_PROFILES_ACTIVE=local ./mvnw spring-boot:run

- 기본 주소는 http://localhost:8082/이다.

- 로그인 후 http://localhost:8082/home에서 홈과 각 메뉴 오버레이를 확인한다.

- 브라우저 개발자 도구의 반응형 모드로 위 검증 크기를 차례로 적용한다.

- npm run build:home으로 React 번들을 다시 생성하고 git diff --check로 변경 파일의<br>공백 오류를 확인한다.

- 실행 중인 Spring Boot가 새 정적 파일을 404로 응답하면<br>./mvnw resources:resources로 target/classes를 갱신하거나 서버를 재시작한 뒤<br>브라우저를 강력 새로고침한다.

오버레이 UI 통합

- 도움말의 콘텐츠 구성은 유지하고 진행, 내 정보, 기수, 학습 기록, 공간, 커뮤니티,<br>설정 오버레이에 공통 시각 체계를 적용했다.

- 오버레이 헤더에 기능 아이콘, 영문 분류, 한 줄 설명을 추가해 첫 화면에서 목적을<br>바로 파악할 수 있게 했다.

- 에메랄드 배경과 오프화이트 카드, 검정 픽셀 테두기는 홈과 공유하고 기능별 포인트<br>색만 달리해 서로 구분되면서도 한 서비스처럼 보이도록 했다.

- 탭, 카드, 빈 상태, 검색, 입력 폼, 페이지 이동, 설정 메뉴의 모서리·그림자·포커스<br>규칙을 통일했다.

- 760px 이하에서는 오버레이를 하단 시트 형태로 배치하고, 430px 이하에서는 헤더<br>설명을 숨겨 실제 콘텐츠 공간을 확보한다.

홈 퀵 패널 UI 통합

- 채팅, 퇴실, BGM, 출석, 재실 버튼을 공통 아이콘·라벨·포커스 규칙을 사용하는<br>퀵 액션 도크로 통합했다.

- BGM, 출석부, 실습실 재실 패널에 공통 아이콘 헤더와 명시적인 닫기 버튼을<br>추가하고 한 번에 하나의 퀵 패널만 열리도록 했다.

- BGM 플레이리스트는 별도 플로팅 창 대신 플레이어 안에서 스크롤되도록 변경했다.

- 760px 이하에서는 세 패널 모두 화면 하단 시트로 전환하고 100dvh 및 safe area를<br>기준으로 최대 높이를 제한해 가로·세로 모바일에서 닫기 버튼과 내부 콘텐츠에<br>계속 접근할 수 있게 했다.

- 출석부는 모바일에서 한 열로 재배치하고 달력 셀과 출석 요약 카드 크기를 줄였다.

- 재실 목록은 모바일에서 검색과 목록 스크롤 영역을 분리해 인원이 많아도 패널 전체가<br>화면 밖으로 밀리지 않도록 했다.

시각 체계 단순화

- 기능별 노랑·파랑·보라·주황·빨강 포인트를 제거하고 홈 초록, 아이보리, 짙은<br>글자색으로 오버레이와 퀵 패널 색상을 통일했다.

- 패널 배경의 그라데이션과 픽셀식 돌출 그림자를 제거하고 얇은 테두리와 낮은 그림자만<br>사용해 콘텐츠가 먼저 보이도록 조정했다.

- 위험 메뉴를 포함한 설정 항목도 별도 빨간 카드 대신 문구로 기능을 구분하고 같은<br>카드 체계를 유지한다.

모바일 레이어 격리 보정

- 일반 메뉴 오버레이는 모바일에서 콘텐츠 길이와 관계없이 viewport 전체 높이를<br>사용하고, 헤더는 고정한 채 본문만 스크롤하도록 변경했다.

- 출석과 BGM 패널이 열리면 배경 경험치 HUD와 하단 도크를 숨기고 패널만 입력을<br>받도록 했다.

- 재실 패널은 도크의 stacking context를 최상단으로 올리되 배경 도크 버튼과 경험치<br>영역은 숨겨 패널 위로 비치거나 겹치지 않게 했다.

- 세로형 모바일뿐 아니라 높이가 짧은 844×390 가로형 모바일에도 동일한 격리 규칙을<br>적용했다.

- 연속 출석 타임라인의 레거시 가상 요소를 모바일에서 제거해 패널 밖으로 긴 가로선이<br>튀어나오지 않게 했다.

React 오버레이 및 모바일 밀도 보정

- 오버레이의 열림·닫힘과 헤더·쉘 렌더링을 HomeOverlayHost React 컴포넌트와<br>useSyncExternalStore 기반 상태 저장소로 이동했다. 기존 home.js는 콘텐츠 데이터와<br>기능 이벤트 처리를 유지한다.

- GUIDE, PROGRESS, SETTINGS, QUICK PLAYER처럼 한글 제목과 의미가 중복되는 영문<br>라벨을 제거하고 한글 제목 하나만 노출한다.

- 모바일 오버레이는 배경만 viewport 전체를 덮고 실제 패널은 콘텐츠 높이만 사용하며,<br>긴 콘텐츠에만 내부 스크롤을 제공한다.

- 진행 탭은 동일한 44px 높이의 가로 픽셀 메뉴로 통일해 선택 탭만 길게 늘어나는 현상을<br>제거했다.

- 설정 카드는 모바일에서도 설명과 액션을 한 행에 유지해 불필요한 세로 여백을 줄였다.

- 하단 도크는 재실·출석·BGM·채팅을 동일한 초록 타일, 픽셀 아이콘, 한글 라벨로<br>통일하고 재실 패널을 열어도 도크 자체의 모양은 바뀌지 않게 했다.

모바일 하단 HUD 정렬

- 1023px 이하에서는 캐릭터 이름·경험치, 메시지 입력창, 퀵 액션 도크를 한 열로<br>배치하고 -home-hud-control-width 하나를 공유하도록 변경했다.

- 기준 폭은 min(100%, 344px)로 두어 좁은 화면에서는 가용 폭까지 자연스럽게<br>줄고, 넓은 화면에서는 항상 같은 좌우 끝과 중앙축을 유지한다.

- 각 영역에 justify-self: center와 동일한 최대 폭을 적용해 viewport 폭이 바뀌어도<br>경험치 바와 입력창, 네비게이션이 한 세로선에서 어긋나지 않게 했다.

- 말풍선과 캐릭터 버튼을 React의 home-character-anchor로 묶고 말풍선 좌표를 이<br>앵커 기준으로 계산한다. 캐릭터 영역 높이가 변해도 말풍선이 상단 안내 문구까지<br>떠오르지 않고 캐릭터 머리 옆을 유지한다.

- 1024px 이상 데스크톱에서는 하단 HUD를 이름 행과 컨트롤 행으로 분리한다.<br>메시지 입력창, 경험치 바, 퀵 액션 도크를 모두 두 번째 Grid 행의 시작선에 배치해<br>서로 다른 컴포넌트 높이 때문에 계단식으로 어긋나지 않도록 했다.

- 낮은 가로 화면용 재배치 조건은 700px~1023px에만 적용해, 높이가 낮은<br>데스크톱 창에 모바일 Grid 규칙이 섞이지 않도록 범위를 제한했다.

설정의 준비 중 기능 처리

- 실제 변경 기능이 없는 비밀번호 항목이 별도의 대형 오버레이를 열지 않도록 했다.<br>설정 목록 안에서 비밀번호 변경 / 현재 준비 중인 기능입니다 / 준비 중 상태를<br>바로 보여주고 비활성 버튼으로 처리한다.

- 더 이상 사용하지 않는 비밀번호 상세 오버레이 데이터와 이벤트 분기를 제거했다.

- 설정 오버레이 자체도 데스크톱 최대 560px의 compact 패널로 줄여 항목이 적은<br>화면에 과도한 가로·세로 여백이 생기지 않도록 했다.

- Octodoro 설정 화면의 정보 구조를 참고해 설정 전용 헤더에서는 큰 아이콘과 설명을<br>숨기고 제목과 작은 닫기 버튼만 남겼다. 본문은 계정 섹션 아래 한 줄 설정 상태와<br>전체 너비 로그아웃 버튼이 이어지는 단일 열 레이아웃으로 재구성했다.

- 설정 패널의 데스크톱 최대 폭을 560px로 제한하고 밝은 카드 묶음 대신 같은 초록<br>계열의 행과 흰색 주요 버튼만 사용해 홈 화면과 어울리는 단순한 위계를 유지한다.

- 모바일에서도 동일한 단일 열 정보 구조를 유지하고 설정 행 내부만<br>minmax(0, 1fr) + auto Grid로 구성해 설명과 상태 배지가 폭에 따라 안정적으로<br>줄어들도록 했다. 340px 이하에서는 글자와 배지 여백만 한 단계 줄인다.

- 모바일 닫기 버튼은 시각적으로는 작은 ×를 유지하되 실제 터치 영역은<br>40×40px로 확보한다.

- 공통 모바일 오버레이가 760px 경계에서 화면 전체 폭으로 늘어나는 규칙을 설정에는<br>적용하지 않고, 모바일·태블릿 모두 최대 560px 중앙 폭을 유지한다.

- 변경된 홈 CSS와 JavaScript URL에 리소스 버전을 추가해 기존 SECURITY 헤더 같은<br>오래된 브라우저 캐시가 새 화면 위에 남지 않도록 했다.

학습 기록 날짜 내비게이션

- 화면 표시용 연도는 2026년 대신 26년으로 줄이고 일간 날짜는<br>26년 8월 18일 화 형식으로 통일했다. 스크린 리더용 aria-label과 툴팁에는<br>2026년 8월 18일 화요일처럼 전체 날짜를 유지한다.

- 기간 이동 화살표는 고정 너비, 날짜는 남은 폭을 사용하는 Grid로 구성하고 날짜에<br>줄바꿈을 금지했다. 480px 이하에서는 오늘 버튼을 숨긴 3열 구조를 사용한다.

- 340px 이하에서는 화살표와 글자 크기만 한 단계 줄여 날짜가 잘리거나 두 줄로<br>떨어지지 않게 했다.

- 900px 이하이면서 높이가 500px 이하인 가로 모바일에서도 탭과 날짜 내비게이션을<br>각각 전체 너비 행으로 쌓아 데스크톱식 양끝 배치가 섞이지 않도록 했다.

캐릭터 말풍선 등장 위치

- 말풍선을 캐릭터 앵커의 상단 중앙 50%에 고정하고 translate(-50%, -100%)로<br>머리 바로 위에 배치했다. 꼬리도 말풍선 중앙을 향하도록 맞췄다.

- 말풍선 레이어를 캐릭터 버튼보다 높게 올려 첫 프레임에 캐릭터 뒤로 숨지 않게 했다.

- 등장 애니메이션은 위치 이동 없이 같은 머리 위 좌표에서 투명도와 크기만 변하도록<br>별도 키프레임으로 교체했다.

공통 오버레이와 진행 화면 재구성

- 도움말과 공간을 제외한 공통 오버레이 헤더를 큰 아이콘·설명형에서 낮은 제목형으로<br>통일했다. 닫기 버튼은 시각적으로 단순하게 유지하면서 40px 조작 영역을 확보한다.

- 진행 오버레이는 데스크톱에서 제목과 퀘스트·업적·랭킹·타임라인·통계 탭을 같은<br>헤더 행에 배치하고, 각 패널에 같은 형식의 섹션 제목과 보조 문구를 제공한다.

- 퀘스트·타임라인·통계는 같은 밝은 단색 목록 행으로 통일했다.

- 업적은 기능이 준비되기 전까지 빈 상태 안내만 표시한다.

- 랭킹은 데이터가 있을 때 동일한 목록 행으로 표시하며, 데이터가 없으면 가짜 순위 없이 빈 상태를 표시한다.<br>금·은·동의 강한 색상 대신 홈의 초록과 투명도 차이만 사용한다.

PC 재실 패널 잘림 수정

- 재실 패널은 빠른 실행 바 내부에서 위쪽으로 펼쳐지는 구조인데, PC 빠른 실행 바의<br>overflow-x: auto가 세로축까지 함께 잘라 패널이 열린 뒤에도 보이지 않았다.

- 패널이 열린 동안에만 :has(.presence-panel:not([hidden]))로 빠른 실행 바의<br>overflow를 해제한다. 닫힌 상태에서는 기존 가로 오버플로 동작을 유지한다.

- PC와 모바일 모두 같은 React 재실 버튼과 aria-expanded 상태를 사용한다.

커뮤니티 오버레이 단순화

- 커뮤니티의 큰 흰색 툴바·공지·빈 결과 카드를 제거하고 진행 화면과 같은 저채도<br>초록 행 구조로 통일했다.

- 필터, 검색, 글쓰기를 한 줄 도구 모음으로 정리하고 페이지가 하나뿐이면 1 / 1<br>페이지 이동 영역을 숨긴다.

- 검색 조건이 없을 때는 아직 게시글이 없습니다, 검색 중에는 검색 결과가 없습니다<br>문구를 구분한다.

- 760px 이하에서는 필터를 첫 행 전체 너비로, 검색과 글쓰기를 둘째 행으로 배치한다.<br>게시글 메타 정보도 제목 아래로 내려 좁은 화면에서 가로 잘림을 막는다.

BGM·내 정보·출석 정리

- BGM 패널 제목 영역에 중복으로 표시되던 트랙 아이콘 가상 요소를 제거했다. 패널<br>헤더의 아이콘 하나만 유지한다.

- 내 정보는 여러 개의 흰 카드 대신 하나의 게임 상태창 구조로 변경했다. 로컬 저장소에<br>존재하는 계정 ID, 닉네임, 캐릭터명, 기록된 학습 시간, 세션, 출석을 사용하며 기수<br>연결 정보가 없으면 미연결로 표시한다. 백엔드 데이터는 임의로 가정하지 않는다.

- 출석 현황은 화면 우측 하단이 아닌 뷰포트 중앙의 고정 패널로 열고, 열린 동안 하단<br>빠른 실행 바를 숨긴다. 달력 제목은 한 줄을 유지하도록 크기와 열 너비를 조정했다.
