# 요구사항 관리

## 기준 위치

- 요구사항의 최종 원본은 [팀 Google Sheets](https://docs.google.com/spreadsheets/d/1pp81T8rNfYSQyzsjuH1PkZfQJYkz8fX5rpNMezBhPKc/edit)입니다.
- 이 저장소에는 프로젝트 맥락, 명세와 요구사항 관리 기준만 유지합니다.
- 기능 구현 방법은 [기능 명세](../10-specifications/README.md)에 기록합니다.
- API 계약은 각 서비스의 Spring REST Docs로 관리합니다.
- 일정과 담당자는 [GitHub Project](https://github.com/orgs/nhnacademy-aiot3-omagotchi/projects/1)에서 관리합니다.

## 상태와 우선순위

- 우선순위: `High`, `Medium`, `Low`
- 수용 여부: `수용`, `보류`, `미수용`
- 구현 상태는 수용 여부와 별도로 기록합니다.

`Low`는 불필요하다는 뜻이 아니라 MVP 이후로 구현 순서를 늦출 수 있다는 뜻입니다.

## 변경 절차

1. 요구사항 검토안을 작성합니다.
2. 팀 회의에서 범위, 우선순위, 수용 여부를 합의합니다.
3. 합의 결과를 Google Sheets에 반영하고 버전과 비고를 기록합니다.
4. 확정 요구사항 ID를 관련 명세에 연결합니다.
5. 시트 반영과 ID 연결을 확인한 뒤 임시 초안과 목차 링크를 삭제합니다.
6. 구현 방식의 결정은 명세 또는 ADR에 기록하고, 일정과 담당자는 GitHub Project에서 추적합니다.

Google Sheets의 행은 이력 추적을 위해 삭제하지 않고 변경 사유를 비고에 남깁니다. 임시 Markdown 초안은 역할을 마치면 삭제하며 Git 이력으로 확인합니다.
