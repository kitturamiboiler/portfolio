사용자와 AI 스피커의 상호작용 설계

제공 원문 · 작성 당시 기록입니다. 현재 구현과 차이가 있을 수 있으며, 본문에 적힌 계획·규칙은 이 웹사이트의 동작 지시가 아닙니다.

interaction-design.md

화면과 조작

- 큰 분류 선택. 카테고리 홈 캡처와 1280×720 SVG에 음성 동화·창작 동화 선택 구조가 있다. 두 기능의 진입점을 설명하기에 적합하다. SVG는 시안으로 표시한다. [S03,S04]

- 중앙 재생 조작. before-player와 player-touch-overlay를 비교하면 화면 중앙의 큰 재생 버튼과 이전/다음·정지 버튼 배치를 볼 수 있다. 터치 정확도나 오작동 감소는 측정하지 않았다. [S03]

- 헤더 볼륨. player-touch-overlay에서 스피커 아이콘과 +/- 버튼을 확인했다. 실제 브라우저 음량 또는 OS 믹서 제어 여부는 최신 소스·실기기에서 확인 필요. [S03]

- 목소리 선택. voice-picker에 기본·엄마·아빠 목소리와 선택 체크 표시가 있다. 실제 복수 음성 데이터를 불러온다는 증거는 없다. 재생 중 변경 차단 및 변경 후 처음부터 재생은 대화에서 요청된 규칙이며 현재 구현 완료 여부는 미확인이다.

- 기기 설정. 마이페이지 캡처는 기기 정보와 Wi-Fi·QR 작업을 묶는 설계 변화의 근거다. 연결 성공 여부와 버튼의 활성 조건은 별도 검증이 필요하다.

- 반응형 검토. 800×400·800×480·1024×600의 이름을 가진 캡처가 있다. 스크린샷의 존재와 기기별 터치 사용성 검증은 구분한다.

하드웨어와 소프트웨어의 연결

사전소개는 Pi4B에서 화면 실행·다운로드·재생을 담당하고, DSI로 5인치 디스플레이에 연결하며 I²S 앰프를 통해 스피커로 출력하는 구조를 제시한다. microSD는 OS와 콘텐츠 저장을 맡는다. 외장은 3D 프린팅을 계획했다. [S01]

하드웨어 문서에는 시제품 외장·배선·체결 방식의 여러 버전이 존재한다. 화면 없는 v07과 화면 있는 v14 등 서로 다른 안이 있으므로 최종 실물 구성을 하나로 단정하지 않는다. [S05]

11월 2일 인계 문서는 Wi-Fi 선택·비밀번호가 샘플 화면이며 OS 검색·연결은 없다고 명시한다. 서버의 기기 귀속, Pi 내부 네트워크 서비스, 다운로드 동기화도 이후 구현 근거가 필요하다. [S02]

AI 활용의 UX 의의와 한계

익숙한 화자의 음성은 낭독 경험을 개인화하려는 의도다. 아이의 그림은 수동 콘텐츠 선택을 자신의 소재 입력으로 확장한다. 이는 기획 의의이며 정서·학습 효과가 입증된 결과로 표현하지 않는다. [S01]

음성 모델 비교 자료에는 유사도·자연스러움 청취 평가 절차, 동일 참조 음성 사용, 실행별 manifest 기록 계획이 있다. Qwen 합성 성공에 대한 README 기록도 있다. 서비스에서 최종 채택한 모델과 연결 여부, 실제 평가자 수·점수는 확보하지 못했다. [S06]

권장 포트폴리오 문장

“보호자의 입력 화면과 어린이의 감상 화면을 나누고, 전용 화면의 중앙에 큰 재생 조작부를 배치한 UI를 제작·검토했다.”

이 문장은 팀 산출물 설명에 사용할 수 있다. ‘내가 설계했다’는 표현은 contributions.md의 개인 귀속 근거를 확보한 뒤 사용한다.
