# 사용자 이용 과정

[S01]의 기획 흐름과 [S02]의 2026-11-02 프론트 구현 기록을 구분했다. 이후 통합 구현 여부는 확인 필요.

## 보호자와 어린이의 역할

보호자는 자신의 목소리를 등록하고 동화·그림을 선택한다. 어린이는 전용 디바이스에서 콘텐츠를 고르고 감상한다. 연령, 가족 환경, 보호자의 불편 빈도는 조사 데이터가 없어 특정하지 않는다.

| 단계 | 사용자 입력 및 화면 | 처리와 출력 | 확인 수준 |
| --- | --- | --- | --- |
| 기기 연결 | 보호자가 QR 스캔 | 기기 확인·계정 설정 | QR 해석은 당시 동작, 계정·기기 귀속은 로컬 상태 [S02] |
| 목소리 준비 | 직접 녹음 또는 파일 선택, 이름 입력 | 미리듣기와 임시 목록 | 로컬 프론트 기록. 화면 이탈 시 임시 음성 소멸 [S02] |
| Voice Tale | 준비된 동화 선택 | 선택 목소리로 낭독 생성 후 저장·재생 | AI 낭독 생성은 기획 흐름. 당시 서버 복제 미연결 [S01,S02] |
| Image Tale | 그림 1~5장과 이야기 요청 입력 | 이미지 이해 LLM → 동화 → 음성 | AI 처리 구조는 제안. 당시 생성 버튼은 로컬 안내 [S01,S02] |
| 기기에서 선택 | 홈·책 목록·목소리 선택 | 그림·본문과 재생 조작 | 해당 화면 캡처 존재 [S03] |
| 감상 | 재생·일시정지·이전/다음 | 페이지 단위 음성·본문 | 11월 2일 문서는 자동 넘김 없음으로 기록. 이후 자동 넘김 여부 확인 필요 [S02] |
| 저장·오프라인 | 저장된 책 선택 | 캐시 기반 콘텐츠 사용 | Cache Storage 기록 존재. 실제 Pi 오프라인 부팅 검증은 당시 미완료 [S02] |

## 입력 → AI → 결과의 계획 구조

Voice Tale은 동의한 화자의 녹음 → 음성 등록/복제 → 동화 텍스트 → 음성 합성 → 파일 저장 → 디바이스 재생 순서다.
Image Tale은 그림과 요청 → 이미지 이해·이야기 생성 → 선택 목소리의 음성 합성 → 페이지별 그림·본문·음원 → 저장·재생 순서다. [S01]

사용자가 생성 상태를 확인하도록 queued/processing/ready/failed 상태를 제안했지만, 이 상태 API가 구현됐다는 증거는 없다. [S02]

## 시연 구성 추천

모바일 목소리 파일 선택·미리듣기 → 그림 입력 → 기기 홈에서 종류 선택 → 저장된 책 재생 → 화면을 눌러 중앙 조작부 표시 순서로 장면을 수집한다. 현재 실제 AI 생성이나 기기 전송이 확인되지 않은 구간은 영상에서 기획 화면으로 표시한다.
