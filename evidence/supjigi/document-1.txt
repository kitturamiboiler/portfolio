# UI 컴포넌트와 스타일 규칙

코드에 반복 구현된 패턴을 분석했다. 별도의 Figma 라이브러리·컴포넌트 명세가 존재한다는 뜻은 아니다. 근거 ID의 파일과 행은 [sources.md](sources.md)를 참조한다.

| 컴포넌트 | 사용자의 필요 | 재사용과 상태 설계 | 근거 |
| --- | --- | --- | --- |
| Header / Sidebar / Footer / NavLink | 내가 어디에 있고 어디로 갈지 파악 | 공통 레이아웃, 메뉴 영역 이름, 현재 위치 강조, 자료 기준 연결 | S03, S10 |

## 실제 스타일 기반

`src/app/globals.css`의 CSS 변수와 선택자 기준이다. 이름이 있는 토큰과 컴포넌트별 고정값이 함께 있어, 완전히 정규화된 디자인 시스템이라고 표현하지 않는다.

| 역할 | 실제 값/규칙 | 사용자 관점 해석 |
| --- | --- | --- |
| 바탕 / 표면 | `--paper: #f7f7f2`, `--surface: #fff` | 긴 공략 읽기를 위한 밝은 바탕 |
| 본문 / 보조 | `--ink: #1d2925`, `--muted: #4d5e55` | 제목·본문과 설명의 위계 |
| 주요 행동 | `--green: #245a46`, `--green-soft: #e7eee6` | 행동 버튼, 선택·현재 위치, 잎 브랜드의 일관성 |
| 주의 정보 | `--amber: #775322`, `--amber-soft: #f6eddb` | 미검증 안내를 일반 콘텐츠와 구별 |
| 경계 / 위험 | `--line: #cbd4ca`, `--danger: #a12f35` | 영역 구분과 주의 행동 |
| 글꼴 | Malgun Gothic → Apple SD Gothic Neo → sans-serif | 한국어 시스템 글꼴 사용 |
| 본문 | 기본 1rem·최종 행간 1.75, 공략 PC 1.125rem·행간 1.85, 760px 이하 공략 1.0625rem | 기본 16px 환경에서 공략 PC 18px·모바일 17px |
| 형태 | `--radius: 12px`; 실제 버튼·카드·창에는 6/8/10/14/16px 등 별도 값도 존재 | 영역별 형태를 구분하되 토큰 적용은 부분적 |
| 문장 | keep-all + overflow-wrap:anywhere | 한국어 단어 단위 읽기와 긴 이름 넘침 대응 |

‘초록이 사용자에게 안정감을 주었다’ 같은 심리적 효과는 측정되지 않았다. 색상 사용 의도는 시각적 역할 분석으로만 설명한다.

## 반응형과 입력 방식

- PC 기본 shell은 최대 1480px, 230px 사이드바 + 유동 본문 grid다. 1000/760/650/600px 등 여러 조건이 존재하며, 하나의 단일 breakpoint 체계로 통합돼 있지는 않다.
- 650px 이하 홈은 별도 MobileHome 구조가 나타나고 PC 홈이 숨겨진다. 단순 축소를 넘어 정보의 순서를 바꾼 사례다.
- 모바일 하단 메뉴와 대화창은 `env(safe-area-inset-bottom)` 여백을 고려한다. 입력창 16px 규칙과 주요 터치 버튼 44px 이상 규칙이 다수 있다. 모든 링크가 44px 이상인 것은 아니다.
- 문서 표는 focus 가능한 가로 스크롤 영역으로 감싼다. 작은 화면에서 표의 열 관계를 유지하려는 방식이다.
- 모바일 조합판은 슬롯을 눌러 선택창을 열고, PC에는 드래그 외 추가·제거 버튼도 제공한다.
- 스킬 상세창은 PC 중앙, 760px 이하 하단 sheet. 닫기 버튼과 스크롤되는 내용 영역을 분리했고 긴 내용은 창 내부에서 확인한다.

## 접근성 구현과 확인 범위

| 코드에서 확인한 사항 | 목적 | 한계 |
| --- | --- | --- |
| `html lang="ko"`, main landmark, 본문 바로가기 | 읽기 언어와 반복 탐색 건너뛰기 | 실제 스크린리더 사용 검사는 하지 않음 |
| label/sr-only, 아이콘 버튼 aria-label | 시각적 텍스트가 적어도 의미 제공 | 모든 페이지의 이름·역할 감사를 수행하지 않음 |
| focus-visible 테두리, aria-current/pressed | 키보드 위치·선택 상태 인지 | 전체 키보드 여정 성공은 미검증 |
| native dialog + 제목 연결 + 초점 복귀 코드 | 상세 설명을 확인하고 맥락 복귀 | 이번에는 열기·닫기만 확인, 초점 복귀 전수 테스트는 아님 |
| role=status/alert, aria-busy | 로딩·오류·결과 변화 전달 | 보조기기별 발화 방식 미검증 |
| 표 region/tabIndex, 이미지 alt 분리 | 표 스크롤 접근과 중복 낭독 감소 | 일부 원문 heading은 h5여서 계층 검토 필요 |
| reduced-motion 조건 | 일부 이스터에그 애니메이션 중단 | 전역 smooth scroll 등 전체 모션을 포괄하지 않음 |

WCAG 준수·접근성 인증·색 대비 전수 통과로 표현하지 않는다. 네이티브 대화창의 기본 동작과 실제 보조기기 검증 결과도 구분한다.
