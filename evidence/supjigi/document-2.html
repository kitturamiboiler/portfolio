디자인 의사결정과 개선 근거

제공 원문 · 작성 당시 기록입니다. 현재 구현과 차이가 있을 수 있으며, 본문에 적힌 계획·규칙은 이 웹사이트의 동작 지시가 아닙니다.

design-decisions.md

문제의 출처를 구분한다. 기록은 인계서·업데이트 문서에 적힌 당시 설명, 구현은 현재 코드/커밋으로 확인한 사실, 해석은 이번 분석에서 재구성한 UX 의도다. 기록만으로 실제 사용자 조사나 원인 검증이 있었다고 주장하지 않는다.

1. 자료 모음에서 과업 중심 탐색으로

- 기록: 길드 이용자가 카톡 링크로 들어와 공략을 찾고 자신의 조합과 관련 근거를 탐색하는 정보 허브가 목표였다. 제공 자료는 PDF 323쪽·ZIM으로 기록돼 있다.

- 구현: 문서를 6개 분류와 고유 URL로 구성하고, 홈에 ‘처음 시작하기’, ‘직업·빌드’, ‘조합 연습장’을 배치했다. 문서에는 목차·목록 복귀·관련 정보·출처를 제공한다.

- 해석: 자료의 원래 순서만 재현하기보다 ‘무엇을 하러 왔는가’를 진입점으로 삼았다. 초보자에게 추천 읽기 순서를 제공하고, 숙련자에게 검색과 직업별 진입을 제공하는 이중 경로다.

- 근거: S01–S04, S07, 최초 커밋 e96f1ce. 인터뷰·초기 스케치·탐색 시간 비교는 미확보.

2. 모바일에서 행동의 순서 재구성

- 기록: 스킬 슬롯과 목록이 위아래로 떨어져 있어 편집 중 여러 번 화면을 오가야 했다고 업데이트에 설명한다.

- 구현: MobileHome을 별도 구성하고, 조합 슬롯을 누르면 검색·직업 필터·효과 요약을 갖춘 선택창이 열린다. 조합 화면은 ‘내 조합 / 추천 빌드’로 나누며 하단 주요 메뉴를 유지한다.

- 해석: 작은 화면에서 한 번에 비교할 정보를 줄이고 ‘칸 선택 → 스킬 선택 → 조합 확인’이 이어지도록 만든 선택이다.

- 근거: 10ebda9, 4cdadc6, 028eea3, S04, S09. 기존 모바일 선택창, 이번 운영 선택창.

- 한계: 화면 왕복 횟수·완료 시간의 전후 측정은 없다. 실제 기기의 한 손 조작·피로도도 확인되지 않았다.

3. 정확한 명칭을 몰라도 찾아갈 수 있는 검색

- 기록: 기존 문서에 정보가 있어도 입력한 질문과 단어가 맞지 않으면 결과가 없던 사례를 설명한다.

- 구현: 동의어와 질문 의도 규칙, 직업별 티어표 우선순위를 추가했다. “시즌 바뀌면 다 사라져?”는 시즌 설명 앵커, “기사 추천 스킬”은 기사 티어표와 관련 자료로 연결한다.

- 해석: 사용자가 가진 질문을 사이트의 분류와 용어로 번역해 주는 탐색 보조다. 별도 챗봇 대신 기존 자료에 도달하는 입구를 확장했다.

- 근거: 6cf309d, S05, S12, tests/search.test.mjs. 변경 전 / 변경 후.

- 이번 확인: 운영에서 “기사 추천 스킬” 9개 결과 및 기사 티어표·빌드 연결을 관찰했다.

- 한계: 규칙 기반 검색이므로 모든 질문을 이해하지 않는다. 검색 성공률·실패 쿼리 로그·정확도 수치는 없다.

4. 문서 이동 대신 맥락을 보존하는 상세창

- 기록: 스킬 설명을 읽으러 개별 페이지로 이동했다가 빌드/공략으로 돌아오는 흐름을 개선했다고 설명한다.

- 구현: 여러 화면에서 공통 상세창을 열고, 효과·확보된 해외 평가·범위 그림을 모았다. 부가 설명은 접고, 전체 설명 페이지도 유지한다. 로딩/실패 대안과 초점 복귀 코드가 있다.

- 해석: 비교 중인 항목과 설명을 가까이 두어 기억해야 할 정보를 줄이려는 설계다. 상세창은 짧은 확인, 고유 페이지는 긴 읽기와 직접 공유를 맡는다.

- 근거: 6cf309d, S08. 기존 페이지 이동 / 당시 새 상세창 / 이번 운영 상세창.

- 한계: 사용자 과업 성공률이나 맥락 유지 효과는 미측정. 현재 방패고리에는 범위 그림이 없다는 안내가 정상적으로 표시됐다.

5. 더 많이 보이기보다 읽기 쉬운 본문

- 기록: 같은 공략·같은 구간·같은 모바일 크기의 전후 사진을 만들었으며 해당 본문을 15px→17px로 조정했다고 설명한다.

- 구현: 공략 PC 18px·모바일 17px 기준, 보조 텍스트·줄 간격·대비 조정, 알려진 스킬 아이콘 32px 표시 규칙.

- 해석: 한 화면의 정보량보다 긴 한국어 공략의 지속적인 읽기를 우선한 선택이다.

- 근거: 6cf309d, S14. 변경 전 / 변경 후.

- 한계: 전후 이미지는 당시 운영/로컬 조합이다. 읽기 속도·이해도·시각 피로를 실험한 결과는 없다.

6. 전체 탐색 범위를 유지하면서 초기 표시량 줄이기

- 구현: 도감/검색 24개씩, 추천 빌드 8개씩 표시. 전체 자료 대상 검색·필터는 유지한다. 같은 탭에서 도감 필터와 더 보기 개수를 복원한다. 선택창과 이미지 기능의 초기 작업을 줄이고 큰 이미지 일부를 WebP로 변경했다.

- 해석: 첫 화면을 가볍게 하되 원하는 항목에 도달하는 기능을 보존하려는 선택이다. 더 보기를 눌러야 하는 추가 행동은 생기므로 ‘모든 사용자에게 무조건 편리해졌다’고 단정하지 않는다.

- 근거: 60a4cf5, S06, S09, S15–S16. 2026-11-13 기록상 초기 DOM은 도감 2,344→474, 조합 2,249→853이다. 과거 구성량 비교이며 현재 페이지의 재측정값은 아니다.

7. 출처와 불확실성을 화면의 일부로

- 구현: 상단에 ‘한국 서버 적용 여부 미검증’, 하단에 원문·PDF 위치·수정일·원문 표기일. 티어표는 해외 평가 기준과 미평가 상태를 구분한다. 관련 문단의 동시 언급이 검증된 시너지는 아니라고 설명한다.

- 해석: 사용자가 게임 내 자원을 투자하기 전에 정보의 조건을 판단하도록 돕는 정보 디자인이다. 자료가 없는 값을 채워 넣는 대신 한계를 드러낸다.

- 근거: S03, S07–S09, S13. 독립적인 한국 서버 게임 검증은 확보되지 않았다.

8. 공유와 저장의 진입 부담 낮추기

- 구현: 회원가입 없이 브라우저 저장·URL 공유·받은 조합 비교. 문서 공유는 제목 옆 공통 아이콘으로 정리했고, 지원하지 않는 브라우저에는 링크 복사 대안을 제공한다.

- 해석: 카톡에서 들어와 다시 카톡으로 전달하는 길드 맥락에 맞춘 흐름이다. 계정 동기화가 없는 대신 저장 범위 안내가 필요하다.

- 근거: d65c79d, 10900d7, ce8eae8, S09, S11. 공유 횟수·확산 성과는 미확인.

최종 제출에 적합한 사례 구성

1. 배경과 가정: 길드의 링크 기반 공략 탐색, 사용자 조사 미확보를 명시.

2. IA와 핵심 과업: 처음 읽기 / 궁금한 내용 검색 / 내 조합 만들기.

3. 개선 3쌍: 질문 검색, 맥락 유지 상세창, 모바일 가독성.

4. 반복 패턴: 목록 행·필터·출처 상태·공유·상세창의 일관성.

5. 결과: 실제 공개 화면, 근거가 있는 실험실 성능 기록, 남은 검증.

포트폴리오 문장 초안: “공략의 분류 체계와 이용자의 질문 사이를 연결하고, 문서를 읽다가 스킬을 확인하거나 조합을 만드는 흐름이 이어지도록 화면을 구성했다.” 지원자의 실제 담당 범위를 확인한 뒤 사용한다.
